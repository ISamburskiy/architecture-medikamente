# 1. 
Нужно удостовериться, что мы собираем и храним все нужные согласия на обработку перс.данных, включая особенности согласия на обработку данных о здоровье.

# 2. 
Нужно удостовериться, что у нас принята политика по разграничению внутреннего доступа к перс.данным клиентов. Скорее всего доступ должен быть примерно такой:

Мед.специалисты:
- данные о результатах обследования / анализов
- данные о записях к врачу
- данные о состоянии здоровья
- минимальный набор перс.данных (фио, дата рождения, семейное положение)

Ресепешн:
- перс.данные для оформления документов (в т.ч. паспортные данные и др.)
- данные о записях к врачу

Кассир:
- перс.данные для оформления документов

Бухгалтер:
- перс.данные клиентов как контрагентов

По результатам этого нужно настроить разграничение доступа к перс.данным, скорее всего достаточно будет RBAC + тэгирование.

Сейчас перс.данные хранятся просто файлами на общем диске, поэтому разграничение доступа вряд ли возможно, но можно попытаться хотя бы настроить права на доступ к определенным разделам диска и попытаться разграничить данные по соответствующим разделам. Но скорее всего целевой контроль доступа возможен только при переходе с общего диска на корпоративное приложение.

# 3. 
Данные о платежах сейчас дублируются в эксель. Это приемлемо, если доступ к папкам с данными о платежах есть только у кассиров (и возможно бухгалтеров). Если это невыполнимо, то адекватный контроль доступа возможен только при переходе на приложение.

# 4. 
Если зарплата платится по реестру, нужно проанализировать возможность того, чтобы реестр попадал в клиент-банк без участия кассира (чтобы у кассира не было к нему непосредственного доступа).

# 5. 

При расширении функционала:

Среди мед.персонала возможно понадобится разделение на "врачей" и "сотрудников лаборатории" (возможно и более детальное в зависимости от перечня оказываемых услуг). В таком случае сотрудники лаборатории при переходе на автоматизацию не должны знать, чьи анализы они сейчас исследуют - им должны быть доступны только медицинские данные.

При появлении личного кабинета потребуется ввести роль "пользователь", который может получить все данные про самого себя (включая согласия на обработку данных).

# 6. 
Нужно разработать корпоративную политику срока хранения данных. С учетом возможности повторных визитов - есть смысл хранить медицинские данные достаточно долго, даже в случае большого перерыва с последнего визита. Но пороговые значения должны быть установлены.


# 7.
При наличии тестовых стендов для разработки и тестирования новой функциональности нужно провести маскировку данных.
