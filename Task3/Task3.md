# Стратегия защиты данных: классификация, необходимость и меры защиты

## Классификация данных и меры защиты

| Данные | В чём необходимость защиты | Инструменты защиты (at rest) | Инструменты защиты (in transit) | Автоматизированный контроль |
|---|---|---|---|---|
| Медицинские карты и диагнозы | Спецкатегория персданных (ст. 10 152-ФЗ). Утечка — штраф до 50 млн ₽, репутационный ущерб, уголовная ответственность | pgcrypto (AES-256, column-level), KMS для сканов | mTLS (Istio) между сервисами, TLS 1.3 для внешних запросов | pgaudit (логирование запросов), Falco (runtime-анализ)|
| Результаты анализов (лаборатория) | Спецкатегория. Содержат сведения о здоровье. Те же риски, что у медкарт | pgcrypto (AES-256), KMS-шифрование в S3 для PDF/JPG | TLS 1.3 при передаче от API лаборатории, HMAC-подпись payload | pgaudit, ELK (корреляция событий), Trivy (сканирование артефактов) |
| Расширенные персданные (адрес, хронические заболевания, место работы) | Комбинация спецкатегории и общих персданных. Максимальный риск ре-идентификации | pgcrypto (AES-256), PostgreSQL Anonymizer для обезличивания при выгрузке в BI/ML | mTLS внутри кластера, TLS 1.3 для API | PostgreSQL Anonymizer (контроль маскирования) |
| Платёжные данные (номера карт — PAN) | PCI DSS. Утечка PAN — штрафы от платёжных систем, потеря эквайринга | Токенизация PAN (хранится только токен), HashiCorp Vault для ключей токенизации | TLS 1.3 + HSTS, network segmentation (PCI VLAN), certificate pinning | Wazuh (FIM на токенах), Falco (anomaly detection), Trivy (secret scanning) |
| Базовые персданные пациентов (ФИО, дата рождения, телефон, email) | 152-ФЗ ст. 3. Утечка — штраф до 6 млн ₽, риск фишинга и мошенничества | pgcrypto (AES-256 для телефона/email)| TLS 1.3 (клиент → портал), mTLS (сервис → сервис) | pgaudit, Keycloak audit log, Victoria Metrics alerting |
| Кадровые данные сотрудников (ФИО, паспорт, СНИЛС, зарплата) | 152-ФЗ + ТК РФ. Утечка — штрафы, трудовые споры, риски для сотрудников | pgcrypto (AES-256), BitLocker для 1С-файлов| TLS 1.3 + mTLS, VLAN сегментация бухгалтерии | pgaudit, Wazuh (FIM), Falco |
| Контракты и договоры с пациентами | Содержат подписи, персданные, условия. Юридическая значимость | MinIO SSE-KMS для PDF-сканов, pgcrypto для метаданных в CRM | TLS 1.3 при загрузке через портал, mTLS между CRM и storage | ELK (audit), Wazuh (FIM) |
| Данные платежей без PAN (суммы, статусы, способы оплаты) | Косвенная связь с персданными. Риск профилирования клиентов |  | mTLS внутри кластера | pgaudit, Victoria Metrics |
| Данные по ТМЦ (складской учёт) | Коммерческая тайна. Раскрытие — конкурентные риски | BitLocker на сервере 1С (если технологий безопасности из коробки окажется недостаточно)| TLS 1.3 между 1С-Склад и 1С-Бухгалтерия (если технологий безопасности из коробки окажется недостаточно) | Wazuh (FIM на 1С-файлах), ELK |
| BI/ML датасеты (агрегированные, обезличенные) | Риск ре-идентификации при недостаточном обезличивании | PostgreSQL Anonymizer (k-anonymity, l-diversity), вывод только через pipeline | mTLS между BI-сервисом и БД, TLS 1.3 для BI-дашбордов |Trivy (сканирование pipeline), Falco |
| Системные логи и аудиторские журналы | Содержат следы доступа к персданным. Сами — источник метаданных | ELK с шифрованием индексов (AES-256), Velero + Restic для бэкапов | TLS 1.3 для shipping логов (Filebeat → ELK), mTLS внутри кластера | Wazuh (целостность логов), Victoria Metrics (метрики алертинга) |
| Резервные копии и бэкапы | Наследуют уровень защиты от источника. Бэкап — частая цель атак | Restic (AES-256 + HMAC-SHA256), KMS-шифрование ключей в Vault | mTLS для репликации (Velero ↔ S3), TLS 1.3 | Velero audit, Trivy (сканирование образов), Wazuh (FIM) |
